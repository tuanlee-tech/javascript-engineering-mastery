## 1. Why This Exists (Vì sao cần học)

Bạn viết:

```js
if (user.age) {
  showProfile(user);
}
```

`user.age` là `0`. Logic skip. Không hiển thị profile.

Bạn debug:

```js
console.log(typeof null);        // "object" ???
console.log(NaN === NaN);        // false ???
console.log(1 / 0);              // Infinity ???
```

Ba dòng code trên đều chạy. Không lỗi. Nhưng kết quả trái ngược trực giác nếu bạn đến từ ngôn ngữ khác.

JavaScript có **7 primitive types**. Mỗi loại có một "vùng giá trị" và behavior riêng. Không phân biệt được `null` vs `undefined`, không hiểu `NaN`, không nhận ra `typeof null` là một trong những nguồn bug phổ biến nhất ở Junior level.

Lesson này xây dựng mental model để bạn **phân loại đúng, dự đoán đúng, và không bị bất ngờ bởi những giá trị "kỳ lạ"**.

## 4. Mental Model (Mô hình tư duy)

:::info Mental Model — Primitive là Giá trị Nguyên tử

Primitive value là **nguyên tử (atomic)**:

- Không thể thay đổi nội dung bên trong (immutable).
- Không có "bộ phận" bạn có thể sửa trực tiếp.
- So sánh bằng **value**, không phải bằng **identity**.

![Primitive value là giá trị nguyên tử](/visualize/stage-00/0.2.3/primitive-value.svg)


Khi bạn "thay đổi" một primitive, bạn không sửa giá trị cũ. Bạn **tạo ra một giá trị mới** và rebind variable.

```js
let s = "hello";
s.toUpperCase();   // Tạo ra "HELLO" — string gốc không đổi
console.log(s);    // "hello"
```

:::

:::tip Code Review Lens
Khi thấy `typeof x === 'object'`, hãy tự hỏi: *"Liệu `x` có thể là `null` không?"* Đây là một trong những guard clause bị bỏ qua nhiều nhất trong code review.
:::

## 5. Core Concepts (Các khái niệm cốt lõi)

### Essential (Bắt buộc)

| Type | Giá trị đại diện | Đặc điểm then chốt |
| ---- | ---------------- | ------------------ |
| **string** | `"hello"` | Immutable sequence of UTF-16 code units. |
| **number** | `42`, `3.14` | IEEE 754 double-precision float. Bao gồm `NaN`, `Infinity`, `-Infinity`. |
| **bigint** | `9007199254740991n` | Số nguyên có độ lớn tùy ý. Không mix với `number`. |
| **boolean** | `true`, `false` | Chỉ hai giá trị. |
| **undefined** | `undefined` | Giá trị mặc định khi variable chưa được gán, hoặc object không có property. |
| **null** | `null` | Giá trị "không có gì" được gán chủ đích. |
| **symbol** | `Symbol('desc')` | Unique identifier, thường dùng làm object key. |

### Supporting (Hỗ trợ)

- `typeof` trả về string đại diện cho type (với edge case ở `null`).
- `Object.is(a, b)` so sánh chặt chẽ hơn `===` (phân biệt `-0` và `0`, `NaN` và `NaN`).

### Awareness (Biết tồn tại)

- **IEEE 754** là spec định nghĩa cách `number` hoạt động ở mức bit. Bạn không cần đọc spec, nhưng cần biết `number` không phải số nguyên "thuần túy" như trong nhiều ngôn ngữ khác.
- `Symbol.iterator`, `Symbol.asyncIterator` sẽ được đào sâu ở Stage 2 (Iteration).

### Out of Scope (Không học trong bài này)

- **Type Coercion**: `Number("5")`, `"5" + 3`, `==` vs `===`. Thuộc Module 0.3.
- **String methods chi tiết**: `slice`, `replace`, regex. Thuộc Lesson 0.6.1.
- **Number methods chi tiết**: `toFixed`, `parseInt`, `parseFloat`. Thuộc Lesson 0.6.1.
- **Boxing wrapper**: `new String()`, `new Number()`. Anti-pattern, sẽ đề cập ở Stage 2.

## 6. Worked Example (Ví dụ phân tích từng bước)

Xét đoạn code sau:

```js
let score = Number("abc");
let rank = 1 / 0;
let label = null;

console.log(typeof score);
console.log(typeof rank);
console.log(typeof label);
console.log(score === score);
console.log(Object.is(rank, Infinity));
console.log(Object.is(0, -0));
```

**Step 1 — `Number("abc")`**
```js
let score = Number("abc");
```
`"abc"` không thể chuyển thành số hợp lệ. `Number()` trả về `NaN` (*Not-a-Number*). `NaN` vẫn thuộc type `number`.

**Step 2 — `1 / 0`**
```js
let rank = 1 / 0;
```
JavaScript không throw error khi chia cho 0. Kết quả là `Infinity`, thuộc type `number`.

**Step 3 — `typeof null`**
```js
console.log(typeof null); // "object"
```
Đây là **historical bug** trong JavaScript từ phiên bản đầu tiên. `null` là primitive, nhưng `typeof` trả về `"object"`. Không thể sửa vì sẽ break legacy code.

**Step 4 — `NaN === NaN`**
```js
console.log(score === score); // false
```
`NaN` theo định nghĩa IEEE 754 không bằng bất kỳ giá trị nào, kể cả chính nó. Để check `NaN`, dùng `Number.isNaN()`.

**Step 5 — `Object.is` với `Infinity`**
```js
console.log(Object.is(rank, Infinity)); // true
```
`Object.is` so sánh giống `===` nhưng xử lý đặc biệt tốt hơn với `NaN` và signed zero.

**Step 6 — `Object.is(0, -0)`**
```js
console.log(Object.is(0, -0)); // false
```
`===` coi `0` và `-0` là bằng nhau. `Object.is` phân biệt được. Điều này quan trọng trong một số thuật toán toán học và animation libraries.

## 7. Prediction Exercise (Bài tập dự đoán)

**Đừng chạy code.** Dự đoán output và giải thích bằng mental model về primitive domain.

**P1**
```js
console.log(typeof NaN);
console.log(typeof undefined);
```

**P2**
```js
console.log(null == undefined); // loose equality — sẽ học chi tiết ở Module 0.3
console.log(null === undefined);
```

**P3**
```js
console.log(1 / -0);
console.log(Object.is(1 / -0, -Infinity));
```

**P4**
```js
let value = 0;
console.log(Object.is(value, -0));
value = -1 * 0;
console.log(Object.is(value, -0));
```

**P5**
```js
const id = Symbol("user");
const id2 = Symbol("user");
console.log(id === id2);
console.log(typeof id);
```

:::details [Đáp án & Giải thích]

**P1**
- `typeof NaN` → `"number"` (NaN là một giá trị đặc biệt trong domain number).
- `typeof undefined` → `"undefined"`.

**P2**
- `null == undefined` → `true` (loose equality coi chúng tương đương).
- `null === undefined` → `false` (khác type: `null` là null, `undefined` là undefined).

**P3**
- `1 / -0` → `-Infinity` (chia dương cho âm zero).
- `Object.is(1 / -0, -Infinity)` → `true`.

**P4**
- `Object.is(value, -0)` lần 1 → `false` (value là `0`).
- `Object.is(value, -0)` lần 2 → `true` (value là `-0`).

**P5**
- `id === id2` → `false` (mỗi Symbol là unique, dù description giống nhau).
- `typeof id` → `"symbol"`.

:::

## 8. Implementation Lab (Bài lab thực hành)

### Lab A — Guided (Có hướng dẫn)

Viết hàm `getRealType` trả về type chính xác của một giá trị, xử lý đúng trường hợp `null`:

```js
function getRealType(value) {
  // TODO: nếu value === null, trả về "null"
  // TODO: nếu không, dùng typeof
}
```

:::details [Đáp án tham khảo]

```js
function getRealType(value) {
  if (value === null) return "null";
  return typeof value;
}

console.log(getRealType(null));      // "null"
console.log(getRealType(undefined)); // "undefined"
console.log(getRealType(42));        // "number"
console.log(getRealType(NaN));       // "number"
```

:::

### Lab B — Partial Scaffold (Khung sườn)

Hoàn thành hàm `safeDivide` sao cho:
- Trả về kết quả phép chia bình thường.
- Nếu `b === 0`, trả về `0` thay vì `Infinity` hoặc `-Infinity`.
- Nếu `a` hoặc `b` là `NaN`, trả về `NaN`.

```js
function safeDivide(a, b) {
  // TODO: check NaN trước
  // TODO: check divide by zero
  // implement here
}
```

:::details [Đáp án tham khảo]

```js
function safeDivide(a, b) {
  if (Number.isNaN(a) || Number.isNaN(b)) {
    return NaN;
  }
  if (b === 0) {
    return 0;
  }
  return a / b;
}
```

:::

### Lab C — Independent (Tự làm)

Viết hàm `normalizeValue` nhận một giá trị đầu vào và trả về giá trị "an toàn":

| Input | Output |
| ----- | ------ |
| `null` | `undefined` |
| `undefined` | `undefined` |
| `NaN` | `0` |
| `Infinity` hoặc `-Infinity` | `0` |
| other | giữ nguyên |

:::details [Đáp án tham khảo]

```js
function normalizeValue(value) {
  if (value === null || value === undefined) {
    return undefined;
  }
  if (Number.isNaN(value)) {
    return 0;
  }
  if (!Number.isFinite(value)) {
    return 0;
  }
  return value;
}
```

## 9. Edge Cases (Các trường hợp ngoại lệ)

:::warning `typeof null === 'object'`

Đây là bug lịch sử. Để check `null` chính xác, luôn dùng:

```js
value === null
```

Không bao giờ dùng `typeof x === 'object'` để infer "đây là object hợp lệ" nếu bạn chưa loại trừ `null`.

:::

:::warning `NaN` là "toxic"

Một khi `NaN` xuất hiện trong chuỗi tính toán, nó sẽ "nhiễm" toàn bộ:

```js
const x = NaN;
console.log(x + 5);      // NaN
console.log(x * 0);      // NaN
console.log(x / 1);      // NaN
```

Và điều nguy hiểm nhất: `NaN` không bằng chính nó, nên `if (x === NaN)` sẽ luôn là `false`.

**Fix:** Dùng `Number.isNaN(x)`.

:::

:::warning `-0` tồn tại

```js
console.log(0 === -0);        // true
console.log(Object.is(0, -0)); // false
```

Hầu hết thời gian bạn không cần quan tâm. Nhưng trong thư viện animation, game engine, hoặc các thuật toán dựa trên dấu, `-0` có thể gây ra behavior khác biệt.

:::

:::warning BigInt không mix với Number

```js
const a = 10;
const b = 10n;
console.log(a + b); // TypeError: Cannot mix BigInt and other types
```

Nếu cần tính toán, phải explicit convert: `BigInt(a) + b` hoặc `Number(b) + a` (nhưng `Number(b)` có thể mất precision).

:::

## 10. Debug Lab (Bài lab gỡ lỗi)

**Symptom (Triệu chứng):** Dashboard hiển thị "N/A" cho tất cả users có tuổi là `0`.

**Reproduction (Tái hiện lỗi):**

```js
function formatAge(age) {
  if (!age) {
    return "N/A";
  }
  return `${age} tuổi`;
}

console.log(formatAge(25));  // "25 tuổi"
console.log(formatAge(0));   // "N/A"  ← BUG
console.log(formatAge(null)); // "N/A"
```

**Evidence (Bằng chứng):**
- `formatAge(0)` trả về `"N/A"` dù `0` là một tuổi hợp lệ.
- `!age` coi `0` là falsy.

**Hypothesis (Giả thuyết):**
Developer dùng `!age` để check "không có dữ liệu", nhưng `0` là falsy nên bị bắt nhầm.

**Verification (Xác minh):**

```js
console.log(!0);      // true
console.log(!null);   // true
console.log(!undefined); // true
```

Cả ba đều vào nhánh `"N/A"`, nhưng chỉ `null` và `undefined` nên vào nhánh đó.

**Root Cause (Nguyên nhân gốc rễ):**
Nhầm lẫn giữa **falsy** và **"không có dữ liệu"**. `0` là một giá trị number hợp lệ, không phải thiếu dữ liệu.

**Fix (Sửa):**

```js
function formatAge(age) {
  if (age === null || age === undefined) {
    return "N/A";
  }
  return `${age} tuổi`;
}
```

Hoặc nếu muốn ngắn gọn và rõ ràng:

```js
function formatAge(age) {
  if (age == null) { // chỉ bắt null và undefined
    return "N/A";
  }
  return `${age} tuổi`;
}
```

**Prevention (Phòng ngừa):**
- Không dùng `!value` để check "thiếu dữ liệu" nếu `0`, `""`, hoặc `false` là giá trị hợp lệ trong domain.
- Dùng `=== null || === undefined` hoặc `== null` khi muốn loại trừ cả hai.

## 11. Design Exercise (Bài tập thiết kế giải pháp)

:::info Context
Bạn đang viết một hàm `mergeConfig(defaults, overrides)`. `overrides` có thể là object, nhưng một số property trong `overrides` có thể được set thành `null` với ý nghĩa "gỡ bỏ giá trị mặc định", trong khi `undefined` có nghĩa "giữ nguyên giá trị mặc định".
:::

```js
const defaults = { timeout: 5000, retries: 3 };

mergeConfig(defaults, { timeout: null });      // { timeout: null, retries: 3 }
mergeConfig(defaults, { timeout: undefined }); // { timeout: 5000, retries: 3 }
```

**Câu hỏi:** Viết logic để phân biệt `null` (override thành "không có gì") và `undefined` (bỏ qua, giữ default). Tại sao `typeof` không giúp ích ở đây?

:::details [Đáp án tham khảo]

```js
function mergeConfig(defaults, overrides) {
  const result = { ...defaults };
  for (const key in overrides) {
    if (overrides[key] !== undefined) {
      result[key] = overrides[key];
    }
  }
  return result;
}
```

**Tại sao `typeof` không giúp ích:**
- `typeof null` là `"object"`, `typeof undefined` là `"undefined"`. Nhưng trong context này, bạn không cần check type — bạn cần check **giá trị cụ thể**.
- `null` và `undefined` đều là primitive, nhưng semantic khác nhau: `null` là "đã quyết định không có giá trị", `undefined` là "chưa được cung cấp".

:::

## 12. Production Scenario (Tình huống thực tế)

Backend API trả về JSON:

```json
{
  "price": 0,
  "discount": null,
  "description": null
}
```

Frontend code của đồng nghiệp:

```js
function renderProduct(data) {
  const priceText = data.price ? `$${data.price}` : "Liên hệ";
  const discountText = data.discount ? `-${data.discount}%` : "";
  const descText = data.description || "Không có mô tả";

  return { priceText, discountText, descText };
}
```

**Câu hỏi:**
1. `priceText` sẽ hiển thị gì? Tại sao đây là bug?
2. `discountText` có đúng không?
3. `descText` có đúng không? Nếu API trả về `description: ""` thì sao?

:::details [Đáp án tham khảo]

1. `priceText` → `"Liên hệ"` vì `data.price` là `0` (falsy). Đây là bug: sản phẩm có giá `0` (miễn phí) bị hiển thị như "Liên hệ".
2. `discountText` → `""` (đúng, vì `null` là falsy và đúng semantic "không có giảm giá").
3. `descText` → `"Không có mô tả"` ngay cả khi `description` là `""`. Đây là bug tiềm ẩn: `""` là một mô tả hợp lệ (mô tả rỗng), không phải "không có mô tả".

**Fix:**

```js
function renderProduct(data) {
  const priceText = (data.price === null || data.price === undefined)
    ? "Liên hệ"
    : `$${data.price}`;

  const discountText = data.discount != null ? `-${data.discount}%` : "";

  const descText = data.description != null ? data.description : "Không có mô tả";

  return { priceText, discountText, descText };
}
```

:::

## 13. AI-assisted Exercise (Bài tập với AI)

**Level B — Challenge (Thách thức AI)**

1. **Tự trả lời trước:** Viết ra giấy: tại sao `typeof null === 'object'`? Dùng từ "bug lịch sử" hay "specification" trong câu trả lời của bạn?
2. **Hỏi AI:** "Why does typeof null return 'object' in JavaScript?"
3. **So sánh:** AI có nói đây là "bug" không? Hay AI nói "null represents the absence of an object reference" để biện minh?
4. **Verify:** Đọc đoạn này trên MDN: [typeof null](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/typeof#typeof_null). Documentation dùng từ gì?

:::tip Gợi ý
Nhiều AI sẽ trả lời rằng đây là "implementation detail" hoặc "historical reason" nhưng không giải thích **tại sao không sửa được**. Hãy để ý xem AI có nhắc đến **backward compatibility** và **legacy code** không. Nếu không, bạn đã tìm ra điểm mù.
:::

:::details Đáp án tham khảo

* **Bạn nghĩ**
  - `typeof null === 'object'` là một bug lịch sử từ phiên bản đầu tiên của JavaScript.
  - Lý do gốc rễ: trong implementation sớm, giá trị type tag của `null` là `0`, cùng với object.
  - Không sửa được vì sẽ break hàng triệu dòng code legacy trên web.

* **AI trả lời**
  - AI thường nói: "This is a well-known quirk in JavaScript. `typeof null` returns `'object'` because in the first implementation of JavaScript, values were represented as type tags and refs, and null was represented as the NULL pointer (0x00), which was interpreted as an object type tag."
  - AI có thể thêm: "It is considered a bug, but fixing it would break existing code."
  - Tuy nhiên, một số AI sẽ nói: "`null` represents the intentional absence of any object value, so it makes sense that typeof returns object." — Đây là **post-hoc rationalization**, không phải lý do kỹ thuật.

* **So sánh**
  - AI đúng về technical mechanism (type tag, NULL pointer).
  - AI thường thiếu: **specification đã ghi nhận điều này như một behavior cố định**, không phải "có thể sửa trong tương lai".

* **Điểm AI nói sai hoặc quá mơ hồ**
  - Câu "null represents the absence of an object reference" gây hiểu nhầm rằng `typeof null === 'object'` là **hợp lý về mặt semantic**. Không phải. Đây là bug được chấp nhận.
  - AI hiếm khi nhấn mạnh rằng ECMAScript spec đã **standardize hóa behavior này**, nghĩa là nó sẽ không bao giờ thay đổi.

* **Kết luận**
  - Nếu bạn chỉ ra được rằng đây là **standardized bug vì backward compatibility**, bạn đã hiểu sâu hơn AI.
  - Concept này sẽ quay lại ở Stage 1 (Value representation) và Stage 6 (TypeScript strict null checks).

:::

:::details Mô phỏng

* **Bạn nói**
  - "`NaN` là một giá trị trong domain `number`. Theo chuẩn IEEE 754, `NaN` được định nghĩa là 'Not-a-Number' và quy tắc nói rõ: `NaN` không bằng bất kỳ thứ gì, kể cả chính nó."
  - "Điều nguy hiểm là `NaN` rất 'toxic'. Nếu một phép tính trả về `NaN` — ví dụ `Number('abc')` — và bạn dùng kết quả đó trong phép tính tiếp theo, `NaN` sẽ lan ra toàn bộ chuỗi."
  - "Và vì `NaN !== NaN`, bạn không thể dùng `if (result === NaN)` để bắt lỗi. Bạn phải dùng `Number.isNaN()`."
  - "Ví dụ thực tế: bạn parse giá trị từ input user, nhận `NaN`, rồi cộng thêm thuế, phí ship — cuối cùng tổng đơn hàng là `NaN`. Khách hàng thấy giá `NaN$` và bạn mất 2 tiếng debug mới biết lỗi bắt nguồn từ một input không hợp lệ 10 bước trước đó."

> 💡 **Liên tưởng:** `NaN` giống như một giọt mực trong ly nước. Một khi nó rơi vào, cả ly nước đều nhiễm. Và bạn không thể nhìn ly nước rồi nói "à, đây là ly nước bị nhiễm" bằng cách so sánh với một ly nước bị nhiễm khác — bạn cần một công cụ test riêng (`Number.isNaN`).

:::

:::tip Gợi ý đánh giá bản thân
- Đồng nghiệp có hỏi "vậy tại sao không sửa spec cho `NaN === NaN`?" không? Nếu có, bạn đã truyền đạt đủ rõ để họ tò mò về backward compatibility.
- Bạn có thể giải thích tại sao `Number.isNaN` khác `isNaN` không? (Gợi ý: `isNaN` có coercion, `Number.isNaN` không.)
- Bạn có thể dự đoán `typeof []` và `typeof (() => {})` không? Nếu kết quả gây bất ngờ, hãy xem tại [Lesson 0.2.4 (Object Values)](./0.2.4-object-values.md).
