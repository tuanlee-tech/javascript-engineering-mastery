## 1. Why This Exists (Vì sao cần học)

Bạn viết một hàm xử lý dữ liệu từ API:

```js
function process(data) {
  if (typeof data === "object") {
    return data.items.map(...);
  }
}
```

API trả về `null` khi không có dữ liệu. Hàm crash với `Cannot read properties of null`.

Bạn kiểm tra input:

```js
console.log(typeof []);       // "object" ???
console.log(typeof null);     // "object" ???
console.log(typeof NaN);      // "number" ???
console.log(typeof (() => {})); // "function" ???
```

`typeof` là công cụ đầu tiên và phổ biến nhất để inspect type trong JavaScript. Nhưng nó không phải type system hoàn hảo. Nó có 8 kết quả cố định, và một số kết quả trong đó là "traps" khiến Junior gặp bug production.

Lesson này dạy bạn **dùng `typeof` đúng chỗ, biết giới hạn của nó, và không bị lừa bởi các kết quả "bất thường"**.

## 4. Mental Model (Mô hình tư duy)

:::info Mental Model — `typeof` là Bộ lọc 8 ngăn

`typeof` không phân tích chi tiết nội dung value. Nó chỉ hỏi engine: *"Value này thuộc category nào trong 8 ngăn sau?"*

![typeof phân loại giá trị JavaScript vào 8 kết quả: undefined, object, boolean, number, bigint, string, symbol và function; array và null đều trả về object.](/visualize/stage-00/0.2.5/javascript-typeof-8-categories.svg)


Quan trọng: `typeof` không có ngăn `"array"` hay `"null"`. Cả hai đều rơi vào ngăn `"object"`.

:::

:::tip Code Review Lens
Khi thấy `typeof x === "object"` trong code review, hãy tự hỏi: *"Tác giả đã loại trừ `null` chưa? Và họ có cần phân biệt array không?"*
:::

## 5. Core Concepts (Các khái niệm cốt lõi)

### Essential (Bắt buộc)

| `typeof` result | Giá trị đại diện | Ý nghĩa |
| --------------- | ---------------- | ------- |
| `"undefined"` | `undefined`, undeclared variable | Không có giá trị được gán hoặc biến chưa tồn tại. |
| `"object"` | `{}`, `[]`, `null`, `new Date()` | Object category. Bao gồm cả `null` (bug lịch sử). |
| `"boolean"` | `true`, `false` | Primitive boolean. |
| `"number"` | `42`, `NaN`, `Infinity` | IEEE 754 double-precision. Bao gồm cả `NaN`. |
| `"bigint"` | `123n` | Số nguyên lớn. |
| `"string"` | `"hello"` | Chuỗi UTF-16. |
| `"symbol"` | `Symbol("x")` | Unique identifier. |
| `"function"` | `() => {}`, `function(){}`, `class {}` | Callable object. `typeof` đặc biệt nhận diện function. |

### Supporting (Hỗ trợ)

- `Array.isArray(value)` để phân biệt array khỏi object thông thường.
- `value === null` để phân biệt `null` khỏi object.
- `typeof` với undeclared variable trả về `"undefined"` (không throw ReferenceError như khi đọc giá trị trực tiếp).

### Awareness (Biết tồn tại)

- `typeof` là operator của language, không phải function (dù thường viết `typeof(x)`).
- `typeof document.all` trả về `"undefined"` ở một số legacy environment (HTML spec quirk). Không cần nhớ, chỉ cần biết `typeof` có thể bị đặc biệt hóa bởi host environment.

### Out of Scope (Không học trong bài này)

- **Prototype chain inspection**: `instanceof`, `Object.prototype.toString.call`. Stage 2.
- **Boxing wrapper**: `new String()`, `new Number()`. Stage 2.
- **TypeScript type guards**: `typeof` ở type-level. Stage 6.

## 6. Worked Example (Ví dụ phân tích từng bước)

Xét đoạn code sau:

```js
function inspect(value) {
  const type = typeof value;
  if (type === "object") {
    return value === null ? "null" : "object-or-array";
  }
  return type;
}

console.log(inspect([]));
console.log(inspect(null));
console.log(inspect(() => {}));
console.log(inspect(42));
```

**Step 1 — `inspect([])`**
```js
typeof [] // "object"
```
Array rơi vào ngăn `"object"`. Hàm check `value === null` → `false`. Trả về `"object-or-array"`.

**Step 2 — `inspect(null)`**
```js
typeof null // "object"
```
`null` rơi vào ngăn `"object"` (bug lịch sử). Hàm check `value === null` → `true`. Trả về `"null"`.

**Step 3 — `inspect(() => {})`**
```js
typeof (() => {}) // "function"
```
Arrow function rơi vào ngăn `"function"`. Hàm không vào nhánh `if (type === "object")`. Trả về `"function"`.

**Step 4 — `inspect(42)`**
```js
typeof 42 // "number"
```
Primitive number. Trả về `"number"`.

**Step 5 — Output**
```js
"object-or-array"
"null"
"function"
"number"
```

```js
function safeTypeOf(value) {
```

```js
function safeTypeOf(value) {
  if (value === null) return "null";
  if (Array.isArray(value)) return "array";

console.log(safeTypeOf(null));      // "null"
console.log(safeTypeOf([1, 2]));    // "array"
console.log(safeTypeOf({}));        // "object"
console.log(safeTypeOf(42));        // "number"
```

```js
function formatForDisplay(value) {
```

```js
function formatForDisplay(value) {
  if (value === null) return "—";
  if (Array.isArray(value)) return `List (${value.length} items)`;
  if (typeof value === "object") return "Object";
```

### Lab C — Independent (Tự làm)

Viết hàm `isValidConfig` kiểm tra một object có phải là config hợp lệ không:

- Phải là object (không phải null, không phải array).
- Phải có property `timeout` là number.
- Phải có property `retries` là number.

Trả về `true` hoặc `false`.

```js
console.log(isValidConfig({ timeout: 5000, retries: 3 })); // true
console.log(isValidConfig(null));                          // false
console.log(isValidConfig([1, 2]));                        // false
console.log(isValidConfig({ timeout: "5s", retries: 3 })); // false
```

:::details [Đáp án tham khảo]


* **Đáp án chấp nhận được :**
  ```js
  function isValidConfig(value) {
      if (value === null || Array.isArray(value)) return false;
      if (typeof value !== "object") return false;
      if (typeof value.timeout !== "number") return false;
      if (typeof value.retries !== "number") return false;
      return true;
  } 
  ```

* **Khi thêm test case:**
  ```js
  console.log(isValidConfig({ timeout: NaN, retries: 3 })); // false
  ```

* **Cần sửa đáp án tham khảo:**

  ```js
  function isValidConfig(value) {
      if (value === null || Array.isArray(value)) return false;
      if (typeof value !== "object") return false;

      if (typeof value.timeout !== "number" || !Number.isFinite(value.timeout)) 
        return false;

      if (typeof value.retries !== "number" || !Number.isFinite(value.retries)) 
        return false;

      return true;
  }
  ```
> **Lý do**
>
>- `typeof NaN === "number"` nên check `typeof === "number"` **chưa đủ** để đảm bảo giá trị hợp lệ. Đây là cơ hội để bạn nhận ra `typeof` chỉ check **type category**, không check **tính hợp lệ về mặt ngữ nghĩa (semantic validity)**.
>
>- `Number.isFinite` đã được dùng ở Lesson 0.2.3 (Lab C — `normalizeValue`). Đây là **spiral reinforcement**: kiến thức 0.2.3 được reuse trong context mới (object property validation).

## 9. Edge Cases (Các trường hợp ngoại lệ)

:::warning `typeof` không bảo vệ khỏi `null`

```js
function getLength(data) {
  if (typeof data === "object") {
    return data.length;
  }
}

getLength(null); // TypeError: Cannot read properties of null
```

`typeof null === "object"` nghĩa là bất kỳ check `typeof x === "object"` nào cũng sẽ để `null` lọt qua. Luôn loại trừ `null` trước.

:::

:::warning `typeof` không phân biệt Array

```js
typeof []        // "object"
typeof {}        // "object"
typeof new Date() // "object"
```

Nếu bạn cần biết chính xác có phải array, dùng `Array.isArray()`. Đây là cách duy nhất reliable cross-frame.

:::

:::warning `typeof` với undeclared variable

```js
console.log(typeof notDefined); // "undefined"
console.log(notDefined);        // ReferenceError
```

`typeof` là cách an toàn để check một biến có tồn tại trước khi dùng. Điều này hữu ích trong các script chạy trên nhiều environment khác nhau.

:::

:::warning `typeof` với BigInt

```js
typeof 1n; // "bigint"
```

`bigint` là kết quả typeof mới (ES2020). Code cũ viết trước 2020 có thể không xử lý case này.

:::

## 10. Debug Lab (Bài lab gỡ lỗi)

**Symptom (Triệu chứng):** Hàm `processPayload` crash với `TypeError` khi API trả về `null`.

**Reproduction (Tái hiện lỗi):**

```js
function processPayload(payload) {
  if (typeof payload === "object") {
    return Object.keys(payload).join(", ");
  }
  return String(payload);
}

console.log(processPayload({ a: 1, b: 2 })); // "a, b"
console.log(processPayload(null));            // TypeError
```

**Evidence (Bằng chứng):**
- `typeof null === "object"` nên hàm vào nhánh `Object.keys(payload)`.
- `Object.keys(null)` throw TypeError.

**Hypothesis (Giả thuyết):**
Developer tưởng rằng `typeof x === "object"` đủ để đảm bảo `x` là object hợp lệ. Họ quên `null`.

**Verification (Xác minh):**

```js
console.log(typeof null); // "object"
console.log(null === null); // true
```

**Root Cause (Nguyên nhân gốc rễ):**
`typeof` không phân biệt `null` và object. Check `typeof` không đủ để safely operate trên object.

**Fix (Sửa):**

```js
function processPayload(payload) {
  if (payload !== null && typeof payload === "object") {
    return Object.keys(payload).join(", ");
  }
  return String(payload);
}
```

**Prevention (Phòng ngừa):**
- Mọi lần dùng `typeof x === "object"`, hãy tự động thêm `&& x !== null`.
- Nếu cần phân biệt array, thêm `&& !Array.isArray(x)`.

## 11. Design Exercise (Bài tập thiết kế giải pháp)

:::info Context
Bạn đang viết một hàm `serializeValue` nhận bất kỳ giá trị nào và trả về string mô tả để log. Yêu cầu:
- `null` → `"null"`
- Array → `"array[n]"` với `n` là số phần tử
- Object → `"object"`
- Function → `"function"`
- Primitive khác → dùng `String(value)`

Bạn không được dùng `try/catch`. Chỉ dùng `typeof` và các check phù hợp.
:::

Viết hàm `serializeValue`. Thứ tự các check có quan trọng không? Tại sao `null` phải check trước `typeof === "object"`?

:::details [Đáp án tham khảo]

```js
function serializeValue(value) {
  if (value === null) return "null";
  if (Array.isArray(value)) return `array[${value.length}]`;
  if (typeof value === "function") return "function";
  if (typeof value === "object") return "object";
  return String(value);
}
```

**Tại sao thứ tự quan trọng:**
- Nếu check `typeof value === "object"` trước `value === null`, `null` sẽ lọt vào nhánh object và bị trả về `"object"` thay vì `"null"`.
- `Array.isArray` phải check trước `typeof === "object"` vì array cũng có `typeof === "object"`.
- `typeof === "function"` phải check riêng vì function không phải object theo `typeof`.

:::

## 12. Production Scenario (Tình huống thực tế)

Backend trả về dữ liệu động từ một endpoint legacy:

```json
{ "result": { "items": ["a", "b"] } }
```

Hoặc:

```json
{ "result": null }
```

Hoặc:

```json
{ "result": ["a", "b"] }
```

Frontend code của đồng nghiệp:

```js
function renderResult(response) {
  const result = response.result;
  if (typeof result === "object") {
    return result.items.join(", ");
  }
  return "No data";
}
```

**Câu hỏi:**
1. `result` là `null` thì sao?
2. `result` là array `["a", "b"]` thì sao?
3. Viết lại hàm để xử lý đúng cả 3 trường hợp.

:::details [Đáp án tham khảo]

1. `result` là `null` → `typeof null === "object"` → vào nhánh `result.items` → `TypeError`.
2. `result` là array → `typeof result === "object"` → `result.items` là `undefined` (array không có property `items`) → `undefined.join(", ")` → `TypeError`.
3. Fix:

```js
function renderResult(response) {
  const result = response.result;
  if (result === null || result === undefined) {
    return "No data";
  }
  if (Array.isArray(result)) {
    return result.join(", ");
  }
  if (typeof result === "object" && Array.isArray(result.items)) {
    return result.items.join(", ");
  }
  return "No data";
}
```

:::

## 13. AI-assisted Exercise (Bài tập với AI)

**Level B — Challenge (Thách thức AI)**

1. **Tự trả lời trước:** Viết ra giấy: tại sao `typeof []` là `"object"` nhưng `typeof (() => {})` lại là `"function"`? Dùng từ "callable" trong câu trả lời của bạn.
2. **Hỏi AI:** "Why does typeof return 'object' for arrays but 'function' for functions, even though both are objects in JavaScript?"
3. **So sánh:** AI có giải thích **tại sao** spec thiết kế như vậy không? Hay AI chỉ nói "because that's how JavaScript works"?
4. **Verify:** Đọc MDN page "typeof operator". Xem documentation có nhắc đến lý do lịch sử của `typeof function` không?

:::tip Gợi ý
Hãy để ý xem AI có nói `typeof` có 8 kết quả cố định hay không. Nhiều AI sẽ trả lời như thể `typeof` là một hệ thống type detection hoàn chỉnh, mà không nhấn mạnh rằng đây là một **operator với 8 string output cố định** — không phải reflection API đầy đủ.
:::

:::details Đáp án tham khảo

* **Bạn nghĩ**
  - `typeof` có 8 kết quả cố định. Không có ngăn "array" hay "callable object".
  - Function được đặc biệt hóa vì chúng là callable. Lịch sử JavaScript cần cách để phân biệt callable object và non-callable object.
  - Array là object thông thường với behavior đặc biệt (ordered, `.length`), nhưng về mặt architecture vẫn là object.

* **AI trả lời**
  - AI thường nói: "Functions are a special type of object that can be called. The `typeof` operator was designed to return 'function' for callable objects because they have special behavior compared to regular objects."
  - AI có thể thêm: "Arrays are technically objects, so `typeof []` returns 'object'. To check for arrays, use `Array.isArray()`."
  - Tuy nhiên, AI hiếm khi nhắc đến **ECMAScript spec** hoặc giải thích rằng đây là **deliberate design decision** từ những ngày đầu để phân biệt callable và non-callable.

* **So sánh**
  - AI đúng về surface behavior.
  - AI thiếu: **8-result limitation** của `typeof`. Nhiều developer tưởng `typeof` là "type system" — nó không phải. Nó là một operator với 8 string cố định.

* **Điểm AI nói sai hoặc quá mơ hồ**
  - AI thường nói "use `typeof` to check the type of a variable" mà không cảnh báo về các edge case (null, array).
  - AI có thể gợi ý `typeof x === "array"` — đây là lỗi nghiêm trọng vì `typeof` không bao giờ trả về `"array"`.

* **Kết luận**
  - Nếu bạn chỉ ra được rằng `typeof` là **operator 8-ngăn cố định**, không phải type introspection hoàn chỉnh, và function được đặc biệt hóa vì callable semantic, bạn đã hiểu sâu hơn AI.
  - Concept này sẽ quay lại ở Stage 2 (Object Model, `Object.prototype.toString`) và Stage 6 (TypeScript type guards).

:::

  - "`typeof` trong JavaScript không phải là một hệ thống phân loại chi tiết. Nó chỉ có 8 kết quả cố định: undefined, object, boolean, number, bigint, string, symbol, và function."
  - "Array, object thông thường, Date, RegExp, Map, Set — tất cả đều rơi vào cùng một ngăn: 'object'. Kể cả `null` cũng rơi vào ngăn này vì một bug lịch sử."
  - "Vì vậy, `typeof []` trả về 'object', giống hệt `typeof {}`. Nếu bạn muốn biết chính xác có phải array, bạn phải dùng `Array.isArray()` — đây là method được thiết kế riêng cho mục đích này và hoạt động đúng cả trong các edge case như cross-frame."

> 💡 **Liên tưởng:** `typeof` giống như một cái máy phân loại rác có 8 ngăn. Tất cả đồ nhựa, giấy, kim loại đều có nhãn riêng — nhưng cái máy này chỉ có một ngăn duy nhất cho tất cả "đồ tái chế". Bạn không thể dùng máy này để biết chai nhựa khác lon nhôm thế nào. Bạn cần một công cụ chuyên dụng khác.
