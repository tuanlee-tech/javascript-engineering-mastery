## 1. Why This Exists (Vì sao cần học)

Bạn nhận dữ liệu từ form input:

```js
const qty = document.getElementById("qty").value; // "3"
const price = 100;

console.log(qty + price); // "3100"  ← BUG
```

`qty` là string. Toán tử `+` thấy string bên trái, nên chuyển `100` thành `"100"`, rồi nối chuỗi. Bạn không cần phép nối chuỗi — bạn cần phép cộng số.

Bạn sửa:

```js
console.log(Number(qty) + price); // 103
```

Nhưng bạn cũng thấy:

```js
console.log(qty - 0 + price); // 103
```

Dấu `-` cũng cho kết quả đúng? Tại sao `+` và `-` lại khác nhau? Và tại sao `Number("")` lại là `0` thay vì lỗi?

Lesson này dạy bạn **kiểm soát conversion** thay vì để JavaScript tự quyết định. Khi bạn hiểu context nào trigger implicit conversion, bạn sẽ biết khi nào cần explicit conversion để bảo vệ logic.

## 4. Mental Model (Mô hình tư duy)

:::info Mental Model — Hai Cách Hỏi "Giá Trị Này Là Gì?"

JavaScript trả lời câu hỏi "Tôi cần giá trị này dưới dạng X" theo hai cách:

**Explicit — Bạn hỏi trực tiếp:**
```text
Bạn: "Hãy cho tôi giá trị này dưới dạng Number."
      ↓
Engine: Number(value)
```

**Implicit — Ngữ cảnh hỏi thay bạn:**
```text
Context: "Tôi là toán tử + và bên cạnh có string."
         ↓
Engine: Tự chuyển đổi sang string để nối.
```

```text
Explicit Conversion          Implicit Conversion
       │                            │
       ▼                            ▼
  Number("42")                "42" + 1 → "421"
  String(42)                  "42" - 1 → 41
  Boolean(1)                  if ("0") → true
```

Quy tắc then chốt: **Nếu bạn không hỏi rõ ràng, JavaScript sẽ đoán ý bạn — và đôi khi đoán sai.**

:::

:::tip Code Review Lens
Khi thấy toán tử `+` giữa giá trị động và string/number, hãy tự hỏi: *"Cả hai operand đã chắc chắn cùng type chưa? Nếu không, ai sẽ bị convert?"*
:::

## 5. Core Concepts (Các khái niệm cốt lõi)

### Essential (Bắt buộc)

| Khái niệm | Ý nghĩa |
| --------- | ------- |
| **Explicit conversion** | Bạn chủ động gọi `Number()`, `String()`, `Boolean()`, `BigInt()`. |
| **Implicit conversion** | Engine tự động chuyển đổi khi gặp ngữ cảnh đòi hỏi type cụ thể. |
| **String context** | Toán tử `+` khi một bên là string → cả hai thành string. |
| **Numeric context** | Toán tử `-`, `*`, `/`, `%`, so sánh `<`/`>` → chuyển thành number. |
| **Boolean context** | `if`, `while`, `&&`, `||`, `!` → chuyển thành boolean (truthy/falsy). |

### Supporting (Hỗ trợ)

- `Number("  42  ")` → `42` (trim whitespace).
- `Number("")` → `0` (empty string → 0).
- `Number(null)` → `0`.
- `Number(undefined)` → `NaN`.
- `String(null)` → `"null"`.
- `String(undefined)` → `"undefined"`.

### Awareness (Biết tồn tại)

- `BigInt()` chỉ nhận integer string/number. `BigInt(1.5)` throw TypeError.
- `parseInt()` và `parseFloat()` khác `Number()`: chúng parse từ đầu chuỗi đến khi gặp ký tự không hợp lệ, không cần toàn bộ chuỗi hợp lệ.

### Out of Scope (Không học trong bài này)

- **ToPrimitive algorithm**: `valueOf`, `toString`, `Symbol.toPrimitive`. Stage 2.
- **Abstract Operations**: `ToNumber`, `ToString` internal spec steps. Stage 2.
- **Date/RegExp conversion**: `new Date()` string parsing. Stage 2.

## 6. Worked Example (Ví dụ phân tích từng bước)

Xét đoạn code sau:

```js
const input = "100";
const bonus = 10;

const total1 = input + bonus;
const total2 = Number(input) + bonus;
const total3 = input - 0 + bonus;

const flag = Boolean("false");
const emptyNum = Number("");

console.log(total1, total2, total3, flag, emptyNum);
```

**Step 1 — `input + bonus`**
```js
"100" + 10
```
`+` thấy một bên là string. Đây là **string context**. Engine chuyển `10` thành `"10"`, rồi nối chuỗi.
**Kết quả:** `"10010"`.

**Step 2 — `Number(input) + bonus`**
```js
Number("100") + 10
```
Bạn **explicitly** chuyển `"100"` thành `100`. Giờ cả hai là number. `+` thực hiện phép cộng số.
**Kết quả:** `110`.

**Step 3 — `input - 0 + bonus`**
```js
"100" - 0 + 10
```
`-` là toán tử số học. Đây là **numeric context**. Engine chuyển `"100"` thành `100`. `100 - 0 = 100`. Rồi `100 + 10 = 110`.
**Kết quả:** `110`.

**Step 4 — `Boolean("false")`**
```js
Boolean("false")
```
Bạn explicitly hỏi boolean của string `"false"`. Theo truthy/falsy rules, chỉ có `""` là falsy. `"false"` là non-empty string → truthy.
**Kết quả:** `true`.

**Step 5 — `Number("")`**
```js
Number("")
```
Empty string trong numeric context được chuyển thành `0`.
**Kết quả:** `0`.

**Output**
```text
"10010" 110 110 true 0
```

Form trả về string. Viết hàm `calculateTotal` cộng price và tax một cách chính xác:

```js
function calculateTotal(priceStr, taxStr) {
  // TODO: chuyển priceStr và taxStr thành number
  // TODO: trả về tổng
}

console.log(calculateTotal("100", "10")); // 110
console.log(calculateTotal("100", ""));   // 100 (tax rỗng = 0)
```

:::details [Đáp án tham khảo]

```js
function calculateTotal(priceStr, taxStr) {
  const price = Number(priceStr);
  // Explicit check "" để rõ ràng: tax rỗng = 0, không phải NaN
  // (Number("") cũng trả về 0, nhưng explicit check giúp code self-documenting)
  const tax = taxStr === "" ? 0 : Number(taxStr);
  return price + tax;
}
```

## 9. Edge Cases (Các trường hợp ngoại lệ)

:::warning `Number("")` và `Number(" ")` đều là `0`

```js
Number("");     // 0
Number(" ");    // 0
Number("\n");   // 0
```

Whitespace-only string được trim rồi parse thành `0`. Điều này có thể gây bug nếu bạn tưởng empty input là invalid.

:::

:::warning `String(null)` vs `null + ""`

```js
String(null);   // "null"
null + "";      // "null"
```

Cả hai đều cho `"null"`. Nhưng nếu bạn không biết input là `null`, bạn sẽ hiển thị chữ "null" cho user — thường không phải ý định.

:::

:::warning `Number(undefined)` là `NaN`, nhưng `Number(null)` là `0`

```js
Number(undefined); // NaN
Number(null);      // 0
```

Hai giá trị "thiếu" nhưng kết quả khác nhau. Đây là một trong những inconsistency phổ biến nhất. Đừng dùng `Number()` để check "có giá trị hay không".

:::

:::warning `BigInt` không nhận float

```js
BigInt(1.5); // TypeError: Cannot convert 1.5 to a BigInt
BigInt("1.5"); // TypeError
```

Nếu cần chuyển float sang BigInt, phải truncate trước: `BigInt(Math.floor(1.5))`.

:::


:::warning `parseInt` vs `Number`

```js
Number("42px");   // NaN
parseInt("42px"); // 42
```
`Number()` yêu cầu toàn bộ chuỗi hợp lệ. `parseInt()` chỉ parse từ đầu đến khi gặp ký tự không hợp lệ. Đây là lý do `parseInt` được dùng để extract số từ string có suffix (ví dụ: `"42px"`), nhưng cũng là nguồn bug nếu bạn tưởng nó validate toàn bộ chuỗi.
:::

## 10. Debug Lab (Bài lab gỡ lỗi)

**Symptom (Triệu chứng):** Tổng tiền đơn hàng hiển thị `"10010"` thay vì `110` khi user nhập quantity.

**Reproduction (Tái hiện lỗi):**

```js
function calculateTotal(price, quantityStr) {
  return price + quantityStr;
}

console.log(calculateTotal(100, "10")); // "10010"  ← BUG
```

**Evidence (Bằng chứng):**
- `price` là number (`100`).
- `quantityStr` là string (`"10"`).
- `+` thấy một bên là string → implicit string conversion.

**Hypothesis (Giả thuyết):**
Developer quên explicit convert `quantityStr` sang number trước khi cộng. `+` trigger string concatenation thay vì numeric addition.

**Verification (Xác minh):**

```js
console.log(typeof 100);        // "number"
console.log(typeof "10");       // "string"
console.log(100 + "10");        // "10010"
```

**Root Cause (Nguyên nhân gốc rễ):**
`+` là toán tử "overloaded": nó nối chuỗi nếu một bên là string, cộng số nếu cả hai là number. Khi input đến từ form/API (luôn string), `+` trở thành string concat.

**Fix (Sửa):**

```js
function calculateTotal(price, quantityStr) {
  const quantity = Number(quantityStr);
  return price + quantity;
}
```

Hoặc defensive hơn:

```js
function calculateTotal(price, quantityStr) {
  const quantity = Number(quantityStr);
  if (Number.isNaN(quantity)) {
    throw new Error("Invalid quantity");
  }
  return price * quantity; // hoặc price + quantity tùy logic
}
```

**Prevention (Phòng ngừa):**
- Mọi giá trị từ form input, query parameter, hoặc API string field phải được explicit convert trước khi dùng trong toán học.
- Không bao giờ dùng `+` giữa giá trị động và string/number mà chưa chắc chắn type.

## 11. Design Exercise (Bài tập thiết kế giải pháp)

:::info Context
Bạn đang viết một hàm `formatDisplay(value)` nhận bất kỳ giá trị nào và trả về string hiển thị UI. Yêu cầu:
- Nếu `value` là `null` hoặc `undefined`, hiển thị `"—"`.
- Nếu `value` là number, hiển thị dạng số (không nối chuỗi).
- Nếu `value` là string, hiển thị chính string đó.
- Nếu `value` là boolean, hiển thị `"Yes"` hoặc `"No"`.

Bạn không được dùng `"" + value` vì nó sẽ implicit convert tất cả thành string một cách không kiểm soát.
:::

Viết hàm `formatDisplay`. Tại sao `String(value)` không phù hợp cho case `null`/`undefined`?

:::details [Đáp án tham khảo]

```js
function formatDisplay(value) {
  if (value === null || value === undefined) return "—";
  if (typeof value === "number") return String(value);
  if (typeof value === "boolean") return value ? "Yes" : "No";
  return String(value);
}
```

**Tại sao `String(value)` không phù hợp cho null/undefined:**
- `String(null)` → `"null"` (hiển thị chữ "null" cho user — không đẹp).
- `String(undefined)` → `"undefined"` (tương tự).
- Cần explicit check `=== null || === undefined` trước khi dùng bất kỳ hàm convert nào.

:::

## 12. Production Scenario (Tình huống thực tế)

Backend API trả về dữ liệu sản phẩm:

```json
{
  "price": "99.99",
  "stock": "0",
  "label": null,
  "active": "true"
}
```

Frontend code của đồng nghiệp:

```js
function renderProduct(data) {
  const price = "$" + data.price;
  const inStock = data.stock > 0;
  const displayLabel = data.label || "No label";
  const isActive = data.active ? "Yes" : "No";

  return { price, inStock, displayLabel, isActive };
}
```

**Câu hỏi:**
1. `inStock` có đúng không khi `stock` là `"0"`?
2. `isActive` có đúng không khi `active` là `"true"`?
3. Viết lại hàm với explicit conversion đúng cho từng field.

:::details [Đáp án tham khảo]

1. `inStock`: `data.stock` là `"0"` (string). `"0" > 0` → implicit numeric conversion: `0 > 0` → `false`. Đúng về mặt kết quả nhưng **fragile** — nếu API đổi thành `"out of stock"`, so sánh sẽ fail silently.

2. `isActive`: `data.active` là `"true"` (string). Non-empty string là truthy. `isActive` → `"Yes"`. Đúng, nhưng nếu API đổi thành `"false"` (string), non-empty string vẫn truthy → `"Yes"` — **BUG**.

3. Fix:

```js
function renderProduct(data) {
  const price = "$" + Number(data.price).toFixed(2);
  const inStock = Number(data.stock) > 0;
  const displayLabel = data.label !== null ? data.label : "No label";
  const isActive = data.active === "true" || data.active === true;

  return { price, inStock, displayLabel, isActive };
}
```

:::

## 13. AI-assisted Exercise (Bài tập với AI)

**Level B — Challenge (Thách thức AI)**

1. **Tự trả lời trước:** Viết ra giấy: tại sao `Number(null)` là `0` nhưng `Number(undefined)` là `NaN`? Dùng từ "intentional absence" vs "uninitialized".
2. **Hỏi AI:** "Why does Number(null) return 0 but Number(undefined) returns NaN in JavaScript?"
3. **So sánh:** AI có phân biệt được semantic khác nhau giữa `null` và `undefined` không? Hay AI chỉ nói "because that's what the spec says"?
4. **Verify:** Đọc MDN page "Number() constructor". Xem documentation có nhắc đến lý do semantic không?

:::tip Gợi ý
Hãy để ý xem AI có giải thích rằng `null` là **intentional absence** (người lập trình chủ động đặt "không có gì") nên có thể map thành `0` (số không), trong khi `undefined` là **chưa được khởi tạo** nên không thể map thành một số hợp lệ → `NaN`. Nhiều AI chỉ liệt kê bảng kết quả mà không giải thích **tại sao** thiết kế như vậy.
:::

:::details Đáp án tham khảo

* **Bạn nghĩ**
  - `null` là "intentional absence of any object value" — người lập trình chủ động đặt "không có gì". Trong ngữ cảnh số, "không có gì" có thể hợp lý hóa thành `0`.
  - `undefined` là "a variable that has not been assigned a value" — chưa được khởi tạo. Không thể biến "chưa biết" thành một số cụ thể → `NaN` (Not-a-Number).
  - Đây là semantic design, không phải random quirk.

* **AI trả lời**
  - AI thường nói: "`Number(null)` returns `0` because `null` represents the absence of a value, which converts to the numeric value `0`. `Number(undefined)` returns `NaN` because `undefined` indicates a variable hasn't been initialized, so it can't be converted to a meaningful number."
  - AI có thể thêm bảng conversion.
  - Tuy nhiên, AI hiếm khi nhấn mạnh rằng đây là **distinction by design** giữa two different "empty" concepts.

* **So sánh**
  - AI đúng về surface explanation.
  - AI thiếu: **hậu quả thực tế** — tại sao điều này quan trọng khi parse API response. Nếu API trả về `null` vs `undefined` cho một numeric field, behavior hoàn toàn khác nhau.

* **Điểm AI nói sai hoặc quá mơ hồ**
  - AI thường nói "null means no value" — mơ hồ. `null` không phải "no value" nói chung; nó là **intentional absence**.
  - AI có thể gợi ý dùng `Number(value)` để sanitize input mà không cảnh báo về sự khác biệt giữa `null` và `undefined`.

* **Kết luận**
  - Nếu bạn chỉ ra được rằng `Number(null) = 0` và `Number(undefined) = NaN` phản ánh **hai khái niệm "trống" khác nhau** trong JavaScript, bạn đã hiểu sâu hơn AI.
  - Concept này sẽ quay lại ở Stage 6 (TypeScript: `null` vs `undefined` trong type system) và Stage 10 (API contract design).

:::

* **Bạn nói**
  - "Toán tử `+` trong JavaScript có hai công việc: nếu một bên là string, nó nối chuỗi. Nếu cả hai là number, nó cộng số."
  - "Với `"5" + 3`, `+` thấy bên trái là string. Đây là **string context**. Nó chuyển `3` thành `"3"`, rồi nối thành `"53"`."
  - "Với `"5" - 3`, `-` chỉ làm một việc: trừ số. Không có 'trừ chuỗi'. Đây là **numeric context**. Nó chuyển `"5"` thành `5`, rồi `5 - 3 = 2`."
  - "Điều này có nghĩa là bạn không thể nhìn toán tử và đoán behavior chỉ bằng trực giác. Bạn phải biết context. Và nếu bạn không chắc type, hãy **explicit convert** trước: `Number("5") + 3`."

> 💡 **Liên tưởng:** `+` giống như một công nhân đa năng. Nếu bạn đưa cho anh ta giấy và keo, anh ta dán. Nếu đưa hai con số, anh ta cộng. Nhưng nếu đưa một giấy và một số, anh ta tự động chuyển số thành giấy rồi dán — vì anh ta ưu tiên dán khi thấy giấy. Còn `-` chỉ biết trừ số, nên khi thấy giấy, anh ta phải đọc số trên giấy rồi mới trừ.

:::

:::tip Gợi ý đánh giá bản thân
- Đồng nghiệp có hỏi "vậy `"5" + "3"` là gì?" không? Nếu có, bạn đã truyền đạt đúng mental model (cả hai là string → nối chuỗi).
- Bạn có thể dự đoán `"5" * "3"` không? (Numeric context → 15.)
:::
